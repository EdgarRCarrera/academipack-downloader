# Security Policy

## Supported versions

| Version | Supported |
|---------|-----------|
| `main`  | Yes       |
| Older commits and unpublished branches | No |

## Reporting a vulnerability

- Prefer GitHub Private Vulnerability Reporting if it is enabled for this repository
- If private vulnerability reporting is not available, do not open a public issue
- Contact the maintainer privately through GitHub first and request a confidential reporting route before sharing details
- Reporting a vulnerability does not authorize intrusive, disruptive or unauthorized testing

## What to include

- Clear reproduction steps using synthetic or redacted fixtures
- The affected file or feature
- Expected impact
- Proof that avoids real secrets, real cookies, real tokens, real LMS HTML and full real URLs

## What not to send

- Passwords
- Cookies
- Session tokens
- Authorization headers
- Browser profiles
- Full HTML exports from real courses
- Full signed URLs or query strings

## Response target

The project aims to acknowledge an initial private report within 7 calendar days.

## Disclosure expectations

- Use coordinated disclosure
- Do not test against real systems without explicit authorization
- Do not attach real course HTML, student data or institutional secrets
- Do not publish exploit details before maintainers have had a reasonable chance to investigate and respond
